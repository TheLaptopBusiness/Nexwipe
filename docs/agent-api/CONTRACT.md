# NexWipe Agent API v1 — production contract

Status: **contract frozen for the first real agent integration (v1.2).** Machine-readable spec: [`openapi.yaml`](./openapi.yaml). Real captured HTTP exchanges: [`transcript.md`](./transcript.md) (generated by `scripts/agent-contract-check.ts`). Curl walkthrough: [`examples.md`](./examples.md). Station authentication design: [`station-auth.md`](./station-auth.md).

Base URL: `https://<app-domain>/api/public/agent/v1`. All bodies are JSON (`content-type: application/json`), max 300 KB per request. Every response carries `x-nd-api-version: 1` and `cache-control: no-store`.

## 1. Endpoints

| # | Purpose | Method + path | Auth | Changes job state |
|---|---|---|---|---|
| 1 | Liveness / clock | `GET /health` | none | no |
| 2 | Enrollment | `POST /enroll` | single-use enrollment token in body | no |
| 3 | Heartbeat | `POST /heartbeat` | station credential | may interrupt stale jobs (server sweep) |
| 4 | Inventory discovery | `POST /inventory` | station credential | no |
| 5 | Authorization retrieval | `GET /jobs` | station credential | no |
| 6 | Acknowledge (start) | `POST /jobs/{id}/ack` | station credential | `queued → running` |
| 7 | Job events | `POST /jobs/{id}/events` | station credential | see §4 |
| 8 | Evidence upload | `POST /jobs/{id}/evidence` | station credential | no |
| 9 | Terminal results | `POST /jobs/{id}/result` | station credential | see §4 |
| 10 | Interruption reconciliation | `POST /reconcile` | station credential | no (instructions only) |
| 11 | Credential rotation | `POST /credentials/rotate` | station credential | no |

The **first real-agent milestone uses only 1–5, 10 and 11** (read-only). Physical stations are enrolled as **read-only test stations**: the server rejects any authorization, job event or evidence for them (`ND403`), so they can never produce an erasure record or a billable job. Endpoints 6–9 must not be called by a real agent until the destructive-testing stage in `agent-handoff/MILESTONES.md` is approved.

## 2. Authentication (every endpoint except 1 and 2)

```
Authorization: Bearer ndagt_<64 hex>
X-ND-Timestamp: 2026-10-31T05:20:43Z      (ISO-8601 or Unix seconds; must be within ±300 s of server time)
X-ND-Nonce: 3f9c2a7e5b1d4c8fa0e6b2d9c7a1f4e3   (16–128 chars [A-Za-z0-9_-], never reused by this station)
```

Order of checks: credential hash lookup → station active → timestamp window → nonce format → nonce unused (stored 15 min, longer than the timestamp window, so any replay inside the window is caught). See `station-auth.md` for limitations.

## 3. Error format and codes

```json
{ "error": { "code": "sequence_conflict", "message": "Expected seq 4", "expected_seq": 4 } }
```

| HTTP | `code` | When | Agent action |
|---|---|---|---|
| 400 | `invalid_json` | body is not JSON | fix client bug; do not retry unchanged |
| 401 | `unauthorized` | bad/revoked credential, used/expired enrollment token, timestamp outside window, missing/malformed nonce | stop; if revoked, wipe credential and require re-enrollment |
| 404 | `not_found` | job not bound to this station (also for other organizations' jobs — existence is never revealed) | drop the job locally |
| 405 | `method_not_allowed` | wrong verb | fix client |
| 409 | `replayed_request` | nonce already used | generate a new nonce and resend |
| 409 | `sequence_conflict` | `seq` ≠ server `last_seq + 1`; see `expected_seq` | reconcile (§6) |
| 409 | `conflict` | invalid transition; authorization used/revoked; idempotency key reused with a different body; job closed | reconcile; never execute |
| 409 | `drive_identity_mismatch` | observed drive or system serial ≠ authorized target; job is quarantined | never execute; show operator |
| 410 | `authorization_expired` | authorization past expiry | wait for a new authorization |
| 413 | `payload_too_large` | body too big | split evidence |
| 422 | `validation_failed` | schema violation (`issues[]` lists paths) | fix client |
| 422 | `unprocessable` | local confirmation missing/wrong, evidence hash mismatch, evidence required, method not permitted | do not execute / re-upload correctly |
| 500 | `internal` | server fault | retry with backoff, same idempotency key, **new nonce** |

## 4. Permitted job-state transitions (server-enforced)

| From | To | Triggered by |
|---|---|---|
| draft | awaiting_authorization | technician submits |
| draft / awaiting_authorization | unsupported | policy does not cover the laptop/drive |
| awaiting_authorization | queued | technician authorizes (asset tag + drive serial re-entered) |
| queued | running | agent `ack` with matching identity + local confirmation |
| queued | awaiting_authorization | authorization expired or station revoked |
| queued | quarantined | identity mismatch at `ack` |
| running | verifying | `result` stage=execution outcome=succeeded with a permitted method |
| running | failed / quarantined | `result` stage=execution outcome=failed (policy decides which) or non-permitted method (quarantined) |
| running | unsupported | `events` type=unsupported |
| running / verifying | interrupted | `events` type=interrupted, revocation, or 180 s without heartbeat/event |
| interrupted | running / verifying | `events` type=resume after re-checking drive identity |
| interrupted | failed / quarantined | `result` reported after restart |
| verifying | awaiting_validation | `result` stage=verification outcome=passed, correct method/sample, evidence present if required |
| verifying | failed / quarantined | verification failed |
| awaiting_validation | approved / quarantined | **human reviewer only** (never the agent) |
| draft / awaiting_authorization / queued | cancelled | technician, only before execution |

Terminal: approved, failed, unsupported, quarantined, cancelled. Any other transition returns 409 `conflict`.

## 5. Sequencing and idempotency

- `ack`, `events` and `result` carry `seq` (per job, starting at 1, = server `last_seq + 1`, no gaps) and `idempotency_key` (8–128 chars, unique per job).
- Same key + same body → original result with `"duplicate": true`, no new event.
- Same key + different body → 409 `conflict`. Wrong `seq` → 409 `sequence_conflict` with `expected_seq`.
- Evidence uploads are idempotent by `idempotency_key` + SHA-256 and do **not** consume a `seq`.
- Retries always reuse the idempotency key and body but use a **new nonce and timestamp**.

## 6. Interruption reconciliation

After boot, network loss or crash the agent must call `POST /reconcile` with every job it has local state for:

| `instruction` | Meaning |
|---|---|
| `continue` | server and agent agree; continue at `next_seq` |
| `replay_from_server_seq` | resend locally logged events after `server_last_seq`, in order, with original keys/bodies |
| `ack_required` | job still queued; local confirmation + `ack` required before any command |
| `report_state` | job is interrupted; re-check drive identity, then send `events` type=resume or a `result` |
| `stop` | job is terminal or no longer bound to this station; discard local state, never execute |

## 7. Authorization binding

An authorization row is bound to **organization + job + station + device + drive association + policy version**, expires (policy lifetime, default 30 min) and is single use. At `ack` the server re-checks: station matches, authorization live and unexpired, job still bound to the same drive association and policy version, observed drive serial (and system serial, if sent) equal the job's target, local confirmation present with the correct last 4 characters. Any mismatch blocks execution. Real stations can never run simulated jobs and vice versa.

## 8. Inventory semantics

- Matches the laptop by system serial and drives by serial **inside the station's organization only**.
- A matched laptop/drive attached to that laptop becomes *station-verified* (`hardware_verified = true`, `source = agent_reported`); browsers can never set these fields.
- Unmatched reports are stored as discoveries and appear under **Agents & stations → Hardware reported by stations**. A technician can add one to inventory; the next heartbeat returns `inventory_requested: true`, and the agent must re-send `POST /inventory` so the server marks it verified.
- Drives flagged `is_boot_medium` or `removable` are never recorded as laptop drives. The agent MUST flag its own boot medium.

## 9. Heartbeat fields (v1.2)

`POST /heartbeat` returns `server_time`, `queued_jobs`, `heartbeat_timeout_seconds`, `inventory_requested`, plus
`mode` (`read_only` | `standard` | `simulated`), `credential_expires_at` and `rotate_recommended` (true when < 14 days remain).
It also returns `reboot_to_usb_requested`, and `diagnostic_requested` + `diagnostic_test` (`full`; boot-stick stations only since migration 0025). Each
command is delivered **exactly once** (next heartbeat flips it on, then off); if no heartbeat picks it up within 2 minutes it expires.

## 9a. Diagnostics (full hardware test)

When a heartbeat returns `diagnostic_requested: true` with `diagnostic_test: "full"` ("Run complete test suite"):
- **Windows helper:** asks the person at the laptop, runs the suite in a local test page (Edge/Chrome), and reports the
  result. It may report only a suite it was handed (409 otherwise); declined / window closed = `"incomplete"`.
- **Boot-stick station:** runs the suite on the laptop screen; it may also report a suite started at the laptop (key T)
  without a request.
Both report (reads hardware only; never touches a disk):
`{ "test": "full", "outcome": "pass" | "fail" | "incomplete", "result": { "layout": "ansi", "tests": { "keyboard": { "outcome", "keys_registered": ["SC_1E", …], "extra_keys": ["LK_224", …], "note"? }, "display" | "webcam" | "microphone" | "speakers" | "touchpad" | "battery" | "charging" | "wifi" | "ports" | "hinges" | "body": { "outcome": "pass" | "fail" | "skipped" | "incomplete", "note"?, "values"?: { name: string | number | boolean | null } (≤ 30) } } }, "detail": "..." }`.
`keyboard` is required. `outcome: "pass"` is refused unless the keyboard passed with ≥ 20 keys and no part failed or is incomplete.
Keys are PC scancode names (physical position, layout-independent); `LK_<code>` are Linux key codes with no scancode (media/Fn).
`"keyboard"` results are accepted only for a keyboard request delivered before 0025. (The 0025 `"handoff"` outcome was removed in 0026.)
Results are recorded against the laptop's device code; they do not change a device grade.

## 10. Credential rotation

`POST /credentials/rotate` (empty body) → `{ "credential": "ndagt_…", "expires_at": "…", "previous_valid_until": "…" }`.
The old credential keeps working for 10 minutes, then expires. Rotating the same credential twice returns 409.
Expired credentials return 401 `"Agent credential has expired; rotate before expiry or re-enroll the station"`.

## 11. Inventory review flags and duplicates (v1.2)

- `system.serial` and `drives[].serial` may be omitted when the hardware does not report one; the report is stored and flagged.
- Optional `review_flags: [{ code, target?, detail? }]` (≤ 50) carries station-side findings. Server adds its own:
  `system_serial_missing`, `system_serial_matches_multiple_devices`, `drive_serial_missing`, `duplicate_drive_serial`,
  `drive_attached_to_other_device`. Codes from the station program: `system_serial_placeholder`, `manufacturer_missing`,
  `model_missing`, `drive_model_missing`, `boot_medium_not_identified`, `no_internal_drives`, `raid_or_vmd_controller`,
  `multiple_nvme_namespaces`, `unsupported_storage`.
- One discovery record per station + laptop: repeat reports (restarts, reconnects) update it and increment `report_count`
  (returned in the response) instead of creating duplicates.
- `station.mode: "read_only"` and `station.image_version` identify the build. `station.hardware_source`
  (`physical` | `virtual` | `synthetic`) is the station's declaration; before 2026-11-01 the HTTP layer dropped this field, so
  every report sent over HTTP was classified synthetic. Fixed; it is now part of the validated schema.
- `drives[].capabilities` (station 0.2.3+): erase features the drive advertises, from ATA IDENTIFY (sysfs, nothing sent to the
  drive) or one NVMe Identify Controller command. Read-only; never evidence that an erase works. `source: "unavailable"` with a
  `reason` when unreadable. Station flags: `drive_capabilities_unknown`, `ata_security_frozen`, `ata_security_locked`.
